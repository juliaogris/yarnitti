## The big bug fixes (so they don't regress)

- **Mobile touch scrub root cause**: every `touch-action` rule was on `<body>`,
  but in spin mode the body has no flow content, so touches land on the root
  `<html>`. `<html>` was `auto`, so the browser claimed the swipe and cancelled
  the pointer stream (pointermove fired 1× per 10 touchmoves). Fix: `touch-action`
  lives on **`<html>`** now — `pan-y pinch-zoom` normally, `none` in spin (an
  `experiment` class is mirrored onto `<html>` in `setExperiment`).
- **Desktop cursor** (grab/grabbing over the mountains) must be set on
  **`document.documentElement`**, not `body` — same reason: the hovered element
  over the mountains is `<html>`. The hover handler is gated by `canHover`, so it
  never runs on touch. Cursor uses the cheap `isInBand`, never `isOnLine`
  per-move (a `getImageData` readback per mousemove caused lag).
- **Scrub de-jank**: do NOT call `syncSliders()` per pointermove (it rewrites all
  six sliders). Use `reflectSlider(param)` for a single cheap value write.

## Architecture note

Discussed rewriting in React/Vue vs staying vanilla. Verdict: **stay vanilla** —
the hard part is the canvas (a framework adds nothing there) and the UI is tiny.
If DX friction grows, adopt **Vite** (dev server + bundler, hot reload, ES
modules) while keeping vanilla JS — no framework.

## Testing approach

Headless Chrome via the DevTools Protocol (Node 26 has a built-in `WebSocket`):
spawn `--headless=new --remote-debugging-port=N`, drive `Input.dispatch*` and
`Runtime.evaluate`, screenshot with `Page.captureScreenshot`. Touch needs
`Emulation.setTouchEmulationEnabled` + `setDeviceMetricsOverride(mobile:true)`.
Headless coalesces touch events, so it undercounts drag deltas — trust it for
"does X fire / does state change", not for exact magnitudes.
